# 发布流程

## 版本规则

人生看板使用 `主版本.次版本.补丁版本`：

- 主版本：产品方向或不兼容的数据结构发生重大变化。
- 次版本：新增一项完整、可使用的产品能力。
- 补丁版本：修复缺陷、部署问题或安全问题，不改变主要用法。

庭院实验保留为 `v0.x`。2026 年 8 月 4 日的人生看板重构从 `v1.0.0` 开始。

## 每次发布

1. 完成功能、迁移、生产构建和必要测试。
2. 更新 `package.json` 中的版本号。
3. 在 `CHANGELOG.md` 顶部记录新增、变更和修复内容。
4. 提交版本资料，确保 `main` 已推送。
5. 在发布提交上创建带说明的 Git 标签。
6. 推送标签，并用同一段说明创建 GitHub Release。
7. 在宝塔服务器执行部署脚本并验证登录、数据库迁移和关键功能。

常规命令如下：

```bash
git tag -a v1.14.0 -m "v1.14.0 - 手机提醒处理闭环"
git push origin main
git push origin v1.14.0
```

标签一旦发布就不移动。后续发现问题时创建新的补丁版本，例如从 `v1.14.0` 发布 `v1.14.1`。

## 历史重建

2026 年 8 月 12 日首次补建版本体系。旧版本标签根据原始提交边界创建，代码、提交时间和提交顺序均未改写；发布说明由对应提交和功能变更整理而来。
