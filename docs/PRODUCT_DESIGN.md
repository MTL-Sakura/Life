# Sakura Life 产品设计文档

相关文档：

- [MVP 页面与交互流程](./MVP_FLOW.md)

## 1. 产品定位

Sakura Life 是一个「人生计划打卡庭院养成」网页应用。

它不是普通待办清单，而是把每天真实要做的事情转化成一个可爱治愈的庭院养成游戏。用户完成学习、健身、睡眠、生活整理、创作等任务后，可以获得资源、经验、属性成长和庭院变化，从而形成稳定的正反馈。

核心目标：

- 降低开始行动的阻力。
- 给每天的小行动即时反馈。
- 允许低能量状态下的最低完成版本。
- 让长期坚持变成可见、可收集、可养成的成长过程。

一句话版本：

> 用每天的小行动，养一座属于自己的樱花庭院。

## 2. 目标用户

第一目标用户是应用作者本人：

- 想学习、健身、完成长期目标，但经常缺少动力。
- 希望有一个温柔的系统推动自己每天行动。
- 不喜欢纯惩罚式打卡，也不想因为一天失败就全盘放弃。
- 希望应用可以手机访问，打开后立刻知道今天要做什么。

后续可以扩展到类似用户：

- 自律困难但愿意被游戏化激励的人。
- 喜欢可爱治愈风格、养成系统、收集系统的人。
- 想把习惯养成、日程目标、复盘统计合在一起的人。

## 3. 设计原则

### 3.1 温柔优先

系统不应该像审判者，而应该像一个陪伴者。失败时不要强调惩罚，而是提供恢复节奏的方式。

### 3.2 小行动也算数

每个任务都应该允许「启动版」完成。例如学习 5 分钟、做 1 组训练、整理桌面 3 分钟。启动成功可以保住节奏，标准完成再给完整奖励。

### 3.3 反馈要立刻发生

用户点击完成任务后，应立刻看到：

- 奖励资源增加。
- 经验条增长。
- 今日进度变化。
- 庭院里某个元素发生细微变化。

### 3.4 第一版保持克制

不要一开始做复杂社交、排行榜、AI 教练、多角色剧情。第一版只服务一个目标：每天愿意打开并完成任务。

## 4. 核心体验

### 4.1 每日核心循环

1. 用户打开应用，看到自己的庭院和今日任务。
2. 用户添加或确认今天要完成的任务。
3. 用户完成现实任务后，在应用里打卡。
4. 系统发放阳光、水滴、樱花币、XP 和属性点。
5. 庭院状态更新，植物成长或装饰解锁。
6. 晚上用户查看今日结算，看到今天做成了什么。
7. 每周进行一次周结算，显示本周趋势和奖励。

### 4.2 情绪曲线

理想的用户感受：

- 打开应用时：今天要做什么很清楚。
- 完成小任务时：我没有停在原地。
- 连续几天后：我的庭院真的在变化。
- 失败一天后：我还能回来，不会被系统否定。
- 一周结束后：我看得到自己比上周多走了一点。

## 5. 游戏主题

### 5.1 世界观

用户拥有一座还很小的樱花庭院。每天完成现实行动，就会获得照顾庭院的资源。

学习让庭院变得更明亮，健身让树木更有生命力，生活整理让道路更整洁，睡眠让植物恢复，创作让庭院出现新的装饰和色彩。

### 5.2 主要资源

- 阳光：主要成长资源，用于植物生长。
- 水滴：维持庭院活力，用于连续打卡、恢复状态。
- 樱花币：购买装饰、主题、称号。
- XP：提升用户等级。
- 花瓣：成就或周结算奖励，作为稀有资源。

### 5.3 用户属性

- 专注：来自学习、阅读、写代码等任务。
- 体能：来自健身、散步、拉伸等任务。
- 秩序：来自整理、清洁、计划等任务。
- 创造：来自写作、绘画、项目开发等任务。
- 恢复：来自睡眠、冥想、休息等任务。

## 6. 任务系统

### 6.1 任务类型

任务由用户自由添加，可以属于以下分类：

- 学习
- 健身
- 睡眠
- 生活
- 创作
- 工作
- 自定义

### 6.2 任务层级

任务分为三层：

- 任务库：长期存在的任务模板，例如「学日语」「健身」「早睡」。
- 今日任务：今天实际要完成的任务，可以从任务库选择，也可以临时添加。
- 打卡记录：每次完成后的历史记录。

### 6.3 完成档位

每个任务可以有三个完成档位：

- 启动版：最低行动，例如学习 5 分钟。奖励少，但保住节奏。
- 标准版：正常目标，例如学习 30 分钟。发放标准奖励。
- 超额版：超过目标，例如学习 90 分钟。发放额外奖励。

示例：

| 任务 | 启动版 | 标准版 | 超额版 |
| --- | --- | --- | --- |
| 学习日语 | 5 分钟 | 30 分钟 | 90 分钟 |
| 健身 | 1 组 | 20 分钟 | 45 分钟 |
| 整理房间 | 3 分钟 | 15 分钟 | 30 分钟 |
| 写代码 | 打开项目并写 1 行 | 45 分钟 | 2 小时 |

### 6.4 奖励计算

第一版可以使用简单规则：

- 启动版：30% 奖励，保留连续。
- 标准版：100% 奖励。
- 超额版：150% 奖励，概率掉落花瓣。

任务难度倍率：

- 简单：1.0
- 普通：1.3
- 困难：1.8
- 史诗：2.5

任务奖励不需要一开始做得非常精确，重要的是用户完成后能立刻感到增长。

## 7. 庭院养成系统

### 7.1 第一版庭院元素

第一版庭院可以先由固定区域组成：

- 中央樱花树
- 草地
- 小路
- 花圃
- 水池
- 装饰位

用户完成任务后，这些区域逐渐变化。

### 7.2 成长方式

樱花树成长可以分阶段：

1. 种子
2. 幼苗
3. 小树
4. 开始长叶
5. 初次开花
6. 满开
7. 夜间灯火
8. 季节主题

不同类型任务影响不同区域：

- 学习：树冠光效、书桌装饰、灯笼。
- 健身：树干生命力、石阶、训练角。
- 睡眠：夜空、月光、庭院恢复状态。
- 生活：小路、围栏、收纳装饰。
- 创作：画架、风铃、特殊花色。

### 7.3 装饰商店

樱花币可以购买：

- 长椅
- 灯笼
- 风铃
- 小桥
- 池塘
- 花盆
- 小书桌
- 季节背景
- 称号展示牌

第一版商店不需要复杂交易系统，只需要简单的购买和摆放。

### 7.4 第一版视觉方向

第一版明确采用 2D 插画风，而不是纯数据仪表盘或极简图标风。

视觉关键词：

- 可爱
- 治愈
- 柔和
- 轻量游戏感
- 樱花庭院
- 手帐感

庭院主视觉建议使用分层 2D 场景：

- 背景层：天空、远景、光线。
- 地面层：草地、小路、水池。
- 主体层：中央樱花树。
- 装饰层：灯笼、长椅、风铃、花盆等。
- 反馈层：花瓣飘落、光点、成长提示。

实现上可以先使用网页原生能力完成：

- 用 CSS 负责整体布局、光影、简单动效。
- 用 SVG 或透明 PNG/WebP 承载插画资产。
- 用状态数据控制树的阶段、装饰显示和场景细节。

第一版不要求复杂动画，但每次完成任务后至少应该有一个清楚的视觉反馈，例如花瓣飘落、树冠变亮、资源飞入面板或装饰解锁提示。

## 8. 正反馈与防崩机制

### 8.1 连续打卡

连续打卡应该鼓励用户回来，但不能成为压力来源。

建议规则：

- 每天完成至少一个启动版任务，就算今日庭院被照顾。
- 完成 3 天、7 天、14 天、30 天解锁奖励。
- 如果中断，可以通过补救任务恢复部分连续。

### 8.2 低能量模式

当用户状态很差时，可以开启低能量模式。

低能量模式下：

- 今日目标自动缩减为 1-2 个小任务。
- 完成启动版也会获得明确肯定。
- 庭院不会枯萎，只是进入安静状态。

### 8.3 冻结卡

冻结卡用于保护连续打卡。

获取方式：

- 每周完成率达到一定比例。
- 连续打卡里程碑。
- 特殊成就奖励。

使用方式：

- 某天未完成任务时自动或手动消耗。
- 保护连续天数不被中断。

### 8.4 周结算

每周结算不只看完美率，而看：

- 完成了多少次启动。
- 完成了多少次标准任务。
- 哪个属性成长最多。
- 哪天状态最好。
- 下周建议降低或提高哪些任务。

## 12. 技术方案

推荐技术栈：

- Next.js：全栈网页应用。
- TypeScript：减少长期维护成本。
- Tailwind CSS：快速做出统一界面。
- Prisma：管理数据库模型和迁移。
- MySQL：适合宝塔面板，部署简单。
- PM2：让 Node 应用常驻运行。
- Nginx：通过宝塔配置反向代理和 HTTPS。
- GitHub Actions：推送代码后自动部署到服务器。

### 12.1 单用户密码登录方案

第一版采用单用户密码登录：

- 不做公开注册。
- 不做找回密码。
- 不做邮箱验证。
- 不做多用户权限系统。
- 只有一个 owner 账号可以进入应用。

推荐实现方式：

- 初始化数据库时创建一个 owner 用户。
- 密码只保存哈希，不保存明文。
- 登录成功后写入加密会话 cookie。
- 所有任务、庭院、打卡记录默认属于 owner 用户。
- 后台管理入口不单独拆分，登录后就是完整应用。

环境变量建议：

```env
APP_OWNER_USERNAME="sakura"
APP_OWNER_INITIAL_PASSWORD="replace-on-first-deploy"
SESSION_SECRET="replace-with-a-long-random-secret"
```

部署后应尽快在应用内或服务器命令中修改初始密码。为了第一版简单可靠，可以先只支持「已登录后修改密码」。

### 12.2 2D 插画实现方案

庭院主视觉采用 2D 插画风：

- 第一版先做固定视角庭院，不做自由移动地图。
- 场景资产按层拆分，便于后续替换和升级。
- 樱花树至少有 6 个成长阶段。
- 装饰物使用固定摆放点，先不做复杂拖拽。
- 手机端优先保证庭院完整可见，任务面板放在庭院下方或可折叠区域。

资产策略：

- 第一阶段可以先使用自制 SVG/PNG 风格资产保证开发速度。
- 稳定后再统一替换为更精致的 2D 插画资产。
- 所有核心资产放在 `public/assets/garden`。
- 装饰资产放在 `public/assets/decorations`。

第一版部署方式建议：

- 服务器运行 Next.js。
- Next.js 监听本机端口，例如 `127.0.0.1:3000`。
- 宝塔 Nginx 把域名反向代理到 `http://127.0.0.1:3000`。
- SSL 在宝塔站点设置里申请和续期。

Docker 可以作为第二阶段再引入。第一版用 PM2 更直观，排错成本更低。

## 13. 宝塔部署流程

### 13.1 服务器准备

在宝塔面板安装：

- Nginx
- MySQL
- Node.js
- PM2 管理器或通过 npm 安装 PM2

### 13.2 域名准备

在域名 DNS 控制台添加 A 记录：

- 主机记录：`life`
- 类型：`A`
- 值：服务器公网 IP

最终访问地址类似：

- `https://life.snowmoon1824.top`

### 13.3 数据库准备

在宝塔创建数据库：

- 数据库名：`sakura_life`
- 用户名：`sakura_life`
- 密码：使用强密码

应用 `.env` 里配置：

```env
DATABASE_URL="mysql://sakura_life:password@127.0.0.1:3306/sakura_life"
APP_OWNER_USERNAME="sakura"
APP_OWNER_INITIAL_PASSWORD="replace-on-first-deploy"
SESSION_SECRET="replace-with-a-long-random-secret"
APP_URL="https://life.snowmoon1824.top"
```

### 13.4 应用部署

服务器目录建议：

```text
/www/wwwroot/life.snowmoon1824.top
```

首次部署流程：

```bash
git clone git@github.com:MTL-Sakura/Life.git /www/wwwroot/life.snowmoon1824.top
cd /www/wwwroot/life.snowmoon1824.top
npm install
npx prisma migrate deploy
npm run build
pm2 start npm --name sakura-life -- run start
pm2 save
```

### 13.5 宝塔反向代理

在宝塔中：

1. 添加网站：`life.snowmoon1824.top`。
2. 打开该网站设置。
3. 进入反向代理。
4. 添加反向代理：
   - 目标 URL：`http://127.0.0.1:3000`
   - 发送域名：`$host` 或保持默认后测试
5. 保存后访问域名。

### 13.6 SSL

在宝塔网站设置里：

1. 进入 SSL。
2. 选择 Let's Encrypt。
3. 申请证书。
4. 开启强制 HTTPS。

## 14. GitHub Actions 自动部署

### 14.1 需要的 Secrets

在 GitHub 仓库：

`Settings` -> `Secrets and variables` -> `Actions`

添加：

- `SERVER_HOST`：服务器 IP。
- `SERVER_USER`：SSH 用户。
- `SERVER_SSH_KEY`：部署私钥。
- `SERVER_PORT`：SSH 端口，通常是 `22`。
- `DEPLOY_PATH`：服务器项目路径，例如 `/www/wwwroot/life.snowmoon1824.top`。

### 14.2 自动部署动作

预期流程：

1. 推送到 `main`。
2. GitHub Actions 连接服务器。
3. 服务器进入项目目录。
4. 拉取最新代码。
5. 安装依赖。
6. 执行 Prisma 迁移。
7. 构建 Next.js。
8. 重启 PM2 应用。

第一版可以等应用代码创建后再写 workflow。

## 15. 开发里程碑

### Milestone 1：项目骨架

目标：

- 初始化 Next.js 项目。
- 配置 TypeScript、Tailwind、Prisma。
- 连接 MySQL。
- 配置单用户密码登录。
- 创建基础布局和主题。

验收：

- 本地可以启动。
- 首页可以访问。
- 数据库连接正常。
